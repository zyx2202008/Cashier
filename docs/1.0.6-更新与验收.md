# Cashier 1.0.6：发票批量导入及排版修复

本版按本轮确认的“销项／进项发票”范围，在 1.0.5 项目上增量修改。客户名录批量导入未纳入本版；既有客户快捷新增、目录折叠及财务计算保留。

## 增补：期间开票与收款统计

“报表 · 往来”新增只读报表「期间开票与收款统计」，报表总数 19 张。支持销项／进项方向切换、快捷期间（本月／上月／本季度／本年度／自定义）及往来单位筛选；发票按登记日期、收付款按业务日期归入期间。红字发票按负数冲减，蓝票张数／红票张数／净张数分列，票款差额仅为本期间含税开票与收付款之差，不受核销状态影响。双击行打开双明细窗口（发票 + 收付款），可一次导出两个工作表。只读报表不写审计、不做关账拦截、不改变资金余额与数据库版本（仍为 2），沿用现有报表查看权限，未新增权限项。

专项测试已扩展至 368 项通过；界面排版矩阵扩展到 40 个菜单页面，覆盖销项／进项切换、快捷期间、1400×820、1080×640 及 125%／150% 模拟缩放、长名称省略与 Tooltip、数值列右对齐、页脚不重叠及横向滚动，并增加本报表六组尺寸／缩放组合，合计 1,475 项断言 0 失败（深度增补见下）。

## 发票批量导入

销项发票、进项发票页面均新增“批量导入”入口，默认选择当前方向；系统工具的“导入导出”入口也保留。

操作：下载当前类型模板 → 按模板填写并选择 Excel → 逐行核对预览 → 确认导入。支持 .xlsx，单次最多 20,000 行。往来单位须已登记且启用，客户／供应商编码、票号、发票代码和原票号按文本填写，保留前导零。模板按当前账套列出可用单位编码，不能凭单位名称猜 ID。

预览显示行号、状态、票号、单位编码及名称、含税金额、不含税金额、税额、税率、原蓝票及日期。价税列优先排列；窄窗口保留横向滚动，不把金额挤进错误列。错误行可“导出校验结果”，原输入值及逐行原因保留，便于修正。

新支持同文件蓝票和红票，红票可以排在蓝票前；写入时先处理有效蓝票，再使用真实原票 ID 登记红票。预览检查方向、单位、原票、日期、税率，以及本批和已登记红票的累计含税／不含税／税额额度。保留票面手工拆分，不强行按税率重算覆盖。

重复号码标记跳过，不覆盖已有发票；错误行须核对并确认后跳过。提交前再次校验账套、预览内容、单位状态、原票身份和期间等约束。提交过程中任一保存或审计失败，整批回滚；不留下前面几行的半批数据。导入后显示登记结果，并防止再次点击同一批次。导入只登记台账，不自动关联业务，也不改变资金余额。

已有的收入／支出 Excel 导入保留。权限沿用 Import + Invoice；未扩大用户角色权限。

## 已处理的排版问题

1. 修复截图中的数值列表头靠左、数据靠右造成的错列观感，数值表头和单元格统一右对齐。使用模拟账套复现了“流入 18,974.86、流出 0、期末 18,974.86”，数值及列关系保持不变。
2. 报表和记账页底部行数、统计期间与合计改为独立换行区域，避免窄窗口重叠。
3. 长单位名、摘要等文本在单元格内省略并裁剪，悬停可看完整内容，避免盖到相邻金额。表格正文不再继承选中页签的粗体。
4. 主窗口标题与操作按钮分列，操作区和工具栏可换行；状态栏分列并省略过长路径。窗口初始尺寸尽量适配工作区。
5. 打印分页把合计行计入行数容量，避免满页后追加合计挤进页脚。长标题、表头、备注及单元格按单行省略，避免固定行高下文字跨行覆盖；完整数据仍可通过 Excel 查看。
6. 导入的自定义发票类型在重新打开编辑时保留原选择。

- ExcelService.cs、InvoiceBatchService.cs：拓展既有导入服务、预览、原票解析、事务提交及校验结果导出；不新增数据库表。
- InvoiceView.xaml.cs、ToolViews.cs：发票页入口、模板／预览／确认／错误导出和导入状态。
- Ui.cs、Theme/Styles.xaml、ReportView.xaml(.cs)、LedgerView.xaml、InvoiceView.xaml、MasterDataView.xaml、MainWindow.xaml(.cs)：列对齐、文本裁剪、换行和窗口排版。
- PrintHelper.cs：合计行分页和固定行高文字控制。
- InvoiceWindow.xaml.cs：自定义历史发票类型回显。
- tests/Cashier.InvoiceBatch：新增专项；Cashier.slnx、run-complex-tests.ps1 纳入原有十个项目和新增项目。
- QaBatchLayout.cs、--qa-batch-layout：明确指定独立 --data-dir 的发布版界面验收模式。
