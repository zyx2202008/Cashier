# Cashier 1.0.5：销项发票快捷新增客户

本版在 Cashier 1.0.4 C# / WPF / SQLite 项目上增量修改。项目根目录为本目录的 Cashier.slnx，目标为 .NET 10，数据库 user_version 仍为 2，无迁移、无新表。正常使用的客户仅存于当前 AppSession.Db 的 partners 表。

## 操作

在“销项发票 → 登记发票”的客户选择旁点击“新增客户”。客户名称必填，可展开填写联系人、电话、地址；编码在保存时自动分配。点击“保存客户并选用”只保存客户；确认发票内容后再点击底部“保存”。

同名时显示具体记录的编码、名称、身份、状态和联系资料。启用的客户及客户兼供应商可明确选用；停用单位和纯供应商不会自动启用、升级或覆盖。确为同名不同单位时，点击相应按钮后还需二次确认，才创建独立客户。

快捷区内回车不会提交发票，Esc 只取消快捷新增，Tab 在快捷区内移动。取消新增不写数据库；客户已经保存后，即使取消发票或发票保存失败，客户仍留在名录。新客户不会自动带入其他客户的红字原票。

管理员、会计可新增。出纳仍只有原有发票权限，快捷入口禁用，可选择已有客户；服务层也独立检查权限。

## 关键修改文件

- src/Cashier.App/Views/InvoiceWindow.xaml、InvoiceWindow.xaml.cs：内嵌快捷区、同名候选与确认、保存状态及键盘处理，保持 ID 绑定和票面字段；LoadOriginals 在客户清空或改变后清除不匹配候选。税率仅实际变化时触发重算，避免失焦覆盖手工票面拆分。
- src/Cashier.App/Views/InvoiceView.xaml.cs：PartnerDirectoryChanged 标志让取消发票后也刷新筛选候选，按原 ID 保留筛选，不强制选择新客户。
- src/Cashier.Core/Services/MasterDataService.cs、InvoiceCustomerService.cs：复用插入和审计 helper；最终重复核对、编码分配、INSERT 及审计在同一连接的立即写事务内完成，提交后返回真实 ID。SavePartner 公开接口和身份保护保留。
- 编码查全部单位（含停用和供应商），从 KH-0001 格式寻找真实空闲编号，不按数量、ID 或最后一条推算，不解析/递增异常大既有编号。仅客户 INSERT 确认发生 partners.code 唯一冲突时最多重试三次；审计或其他失败原样回滚，不冒充编码冲突。
- 同名使用 Trim + OrdinalIgnoreCase，保留内部空格。候选快照含 ID、身份、状态和联系资料，在最终写事务重新核对；集合变化会返回重新确认，不持锁弹窗。选择已有记录只使用其 ID。
- tests/Cashier.InvoiceQuickCustomer、Cashier.slnx、run-complex-tests.ps1：新增服务回归，并保留原九个测试项目。
- App.xaml.cs、QaInvoiceCustomer.cs：显式 --qa-invoice-customer 验收模式，必须提供 --data-dir。测试标记及故障注入只用于独立模拟账套，不进入正式客户存储和交付包。

- 原要求 powershell -NoProfile -File 命令被本机默认脚本策略拦截；审阅后使用仅当前进程的 -ExecutionPolicy Bypass 执行成功，没有修改机器或用户执行策略。依赖从本机现有缓存恢复，版本未改。
- dotnet publish src/Cashier.App/Cashier.App.csproj -c Release -r win-x64 --self-contained true -p:DebugType=none -o dist/app：成功。
- 压缩、重新解压后，直接运行解压出的 Cashier.exe，指定独立 --data-dir；首次 WPF 验收 30 项，关闭并重启同一 EXE 验收 4 项，共 34 项通过。实际新增客户、选用、保存发票、关闭及重启复用均完成。父页面取消后候选刷新、进项/编辑入口、停用客户回显、原票清空、输入保持及故障后按钮恢复也已检查。

## 旧账套兼容

使用 1.0.4 程序生成模拟旧账套，再对副本用新版核心读取。7 条往来单位、5 张发票、资金账户余额、往来余额、业务表逐行指纹一致，user_version=2。模拟账套资金合计为 542,599.82 元。原有 InvoiceService、金额计算、Schema、Database 未改动。此结果不等于真实账套验收。

使用前在旧软件备份真实账套并另存；完整解压软件 ZIP 后双击 Cashier.exe。默认账套仍为 %APPDATA%\Cashier\cashier.db，不同时运行两版本操作同一账套。软件数字签名状态沿用原版本。

## 简短验收步骤

1. 管理员登录，进入销项发票登记，先填发票号码、日期和金额，并手工调整票面不含税金额及税额。
2. 点“新增客户”，填名称，取消一次确认票面字段仍在；再次新增并保存，确认客户被选中，票面拆分未改变。
3. 保存发票；再登记一张，确认该客户可选。另测试保存客户后取消发票，客户名录及父页面候选仍可见。
4. 输入同名名称，明确选择已有记录或确认不同单位；用出纳账号确认只能选择已有客户。
5. 关闭后重启，核对客户及发票的真实关联。新客户没有原蓝票时，不得用其保存缺少原票的红字发票。

源码包不包含测试账套、备份、日志、test-runs、dist 或编译中间文件。服务测试必须使用全新的独立数据目录；不能指向默认或真实账套。
