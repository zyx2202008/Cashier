# 应收应付与月报更新说明

本说明记录应收应付月报初版；当前 1.1.0 的修复和测试以 `1.1.0-深度测试与修复.md` 为准。本更新基于上一轮客户与供应商编码更新的源码。交付包含 Windows 发布程序和完整源码；没有包含真实账套或测试账套。

## 业务规则

- 原系统的已审核应收单、应付单本身就是应收应付业务记录，使用其原有 ID、业务日期、单位、金额和状态，不重复创建另一份账款。现收和现付业务不额外制造应收或应付。
- 应收、应付列表按已有核销关系动态显示“未结清、部分结清、已结清”。付款或收款需要通过原有的手工核销或自动核销操作明确分配到业务；系统不会仅凭单位名称猜测每笔付款的用途。付款/收款审核后，单位汇总余额依据实际收付款计算。
- 发票录入、批量导入启用保守自动匹配：同单位、同方向未关联发票与可关联的已审核应收/应付业务两边均只有一个候选时才关联。多候选、期间关闭、金额超过可关联余额等情况会保留未关联金额并提示核对；可在发票列表中手工分摊。发票先录入、业务后审核时会尝试补关联。发票与账款关联、业务审核、审计和匹配标记在同一事务内处理。
- 旧账套发票和直接使用旧服务接口的调用保持原有手工关联行为；新调用方若需要自动匹配可设置 `Invoice.AutoLink=true`。系统生成的关联有单独标识，历史手工关联不会被当成自动关联覆盖。
- 原发票模块保存的是登记日期和交票日期，没有独立的实际开票日期字段。本次沿用登记日期作为现有发票统计及关联的日期；尚不能单独记录或按实际开票日期统计。
- 自动关联的发票金额减少或作废时，受红票和关账限制保护，关联变更会留存历史并参与回滚。存在手工关联的发票，如修改金额或作废需要调整这些关联，仍需先手工解除；已关联发票变更单位、方向、原票或登记日期也需先解除。蓝票存在有效红票时须先处理红票。发票金额增加时，若已有部分关联不会自动扩充该关联，未关联余额需核对。

## 月报及导出

在报表目录中的“往来”分类选择“供应商应付汇总统计月报表”或“客户应收汇总统计月报表”，选择年度、月份及往来单位后刷新。单位下拉框支持文字搜索；导出 Excel 使用当前显示的查询结果，包含表头、金额和合计行。

本月实收/实付包括预收/预付；期末余额包括期初余额、截至月末已审核业务、收付款及相应退款。已开票金额是截至月末与应收/应付业务实际关联的有效发票净额；未开票金额为截至月末业务金额减去该关联净额。存在异常超额关联时会报错，不生成负数的未开票金额。

**期初口径限制：**原账套只保存期初应收/应付余额，没有区分其中已开票与未开票的金额。因此期末余额包含期初，未开票金额不包含期初；不能把该数字当作包含期初的完整未开票余额。

**历史口径限制：**原系统没有完整的凭证状态和金额历史快照；历史月份按当前有效的已审核凭证重算。后来反审核、修改或作废的凭证不会自动还原成历史当时的状态，因此历史月份不等于不可变的月末快照。发票关联使用已有生效/解除历史计算。

## 数据库变化

本次无需新增业务表或字段，不改变数据库版本；沿用原有 `vouchers`、`settlements`、`invoices`、`invoice_links` 和历史表，并在既有 `meta` 表记录新发票的自动匹配资格及系统关联标识。此前版本 2 账套仍按上一轮规则升级到版本 3，程序会先备份。实际账套未在本次测试中使用。
