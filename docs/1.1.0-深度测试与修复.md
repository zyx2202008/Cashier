# Cashier 1.1.0 深度测试与修复

## 使用

完整解压交付包，打开 `Cashier/Cashier.exe`。应用程序、Core 程序集及 Windows 文件属性版本均为 1.1.0，主界面左上角显示 v1.1.0。升级前关闭同一账套的所有程序并备份账套；不要只复制单个 EXE。

本次在独立合成账套中测试，没有改动真实账套和原始交付 ZIP。当前数据库版本仍为 3，本次没有新增数据表、字段或重建数据；版本 1/2 旧账套仍按现有迁移流程升级并先生成备份。

## 已修复

1. **自动关联未随发票增额补足。**在业务和发票仍唯一匹配、原关联由系统自动建立的条件下，增加发票金额会补足已有自动关联，最高到实际业务可开票余额。蓝票和红票均按各自方向处理。追加前的关联保存到历史表；当前追加金额不回写到过去月份。
2. **人工分配后可能再次自动分配其他业务。**只要一张发票存在人工建立的关联，自动匹配就停止处理该发票，避免改变用户明确选择的用途。解除、重新关联、已关闭期间及有效红票等保护保留。
3. **月报预设月份被当前月份覆盖。**从带筛选参数的入口打开月报时，保留原有年度、月份和单位筛选。
4. **账套核对未发现部分金额异常。**新增发票超关联、业务超开票或无效状态、核销超额、核销单位/方向错误及外键缺失检查。核对只提示异常，不自动修改账务。
5. 清理已验证的空值编译警告及未使用字段，统一程序与程序集版本为 1.1.0，并在主界面显示版本。

## 仍适用的业务边界

本次测试通过不等于对所有真实账套和设备的穷尽保证。以下原有数据和业务限制未凭空补齐：

- 发票只在双方候选唯一且无人工分配时自动匹配，多候选须人工确认；收付款用途仍通过手工/自动核销明确分配。
- 期初余额缺少开票拆分，月报未开票金额不包含未知的期初未开票部分。
- 原系统没有完整的凭证历史快照；历史月份根据当前有效凭证重算，不等于不可变的关账快照。发票关联历史按已有生效/结束日期计算。
- 沿用发票登记日期，尚无独立的实际开票日期字段；人工关联、修改单位/方向/日期及有效红票依赖仍按现有保护要求处理。

以上边界在界面口径和既有更新说明中继续保留，不能把测试结果理解为这些业务能力已新增。
