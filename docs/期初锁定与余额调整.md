# 期初锁定与余额调整（1.2.0）

入口：**系统工具 → 期初与余额调整**。

## 新账套

新建账套处于期初准备状态。先在基础资料中核对资金账户、客户、供应商的期初，再由管理员填写启用日期和确认原因，点击“确认并锁定期初”。正式使用前应完成此确认。

启用日期不得晚于今天，也不得晚于账套已有的最早业务或发票登记日期。确认后，账户期初、客户应收期初、供应商应付期初不能直接修改，也不能直接解锁。姓名、联系电话、账户名称等资料仍可维护。

锁定后新增账户和单位以零期初建立，需要承接余额时登记余额调整。有期初余额或被调整引用的对象保留记录，可停用。

## 更正余额

会计或管理员点击“登记余额调整”，选择账户余额、客户应收或供应商应付，填写对象、生效日期、带正负号的金额和原因。

- 正数增加该余额，负数减少；客户净应收为负仍表示预收，供应商净应付为负仍表示预付。
- 生效日期不能早于登记当天或账套启用日期，不能落入已关闭期间。未来日期的调整在该日才计入当前余额。
- 调整记录保存编号、对象、金额、生效日期、原因、登记人、登记时间，以及登记时的调整前后余额快照。
- 相同窗口重复提交相同请求只产生一条记录；其他内容复用相同提交标识会被拒绝。

例如：10月末余额为1,000元，11月5日登记增加200元的调整并于当天生效，则截至10月末余额仍为1,000元，11月5日计入这200元。真实业务收付应在收入、支出等业务模块登记。

## 撤销更正

选中尚未反向调整的原记录，点击“追加反向调整”，填写生效日期与原因。原记录保留，追加一条等额反向记录。反向记录不能再次反向，原记录只能反向一次；需要继续更正时登记新调整。

反向生效日不能早于原调整生效日、登记当天或启用日，也不能落入已关闭期间。对象停用后仍可冲回既有调整。未来的反向调整不会提前抵销当前余额，也不会改变较早截止日的明细状态。

## 报表与核对

账户报表、账户月年报、客户及供应商汇总、月度应收应付表都计入截至查询日生效的调整，并增加独立调整列。账户资金明细会列示调整记录，便于下钻核对。

账户期末 = 期初 + 业务资金流入 − 业务资金流出 + 本期余额调整。

往来净余额 = 原期初 + 原有往来发生及收付款变化 + 截止日生效调整。

期间起点之前生效的调整纳入期间期初，期间内调整单列。只有调整而没有收付的月份也会出现在账户月年报中。调整不进入业务收入、支出、项目利润、可开票额或核销分配。

调整页面可以按生效日和类型查询、导出 Excel。登记时的余额快照仅记录当次操作的核对状态；后续业务、其他调整或未来生效记录仍按其日期影响余额，不以该快照替代报表计算。

## 旧账套升级与恢复

数据库从v4升级到v5前自动备份。已有单据、发票、非零期初或已关账期间的旧账套会自动锁定期初，原余额不重写；启用日期取已有最早业务日期，没有业务时取升级当天。全新、无业务且期初为零的账套保留准备状态。

启用日期作为期初确认及调整的控制信息，不重新解释原有期初承接数据；以前已经改动的历史不能凭本功能自动还原，需要原备份或原始依据。

备份包含期初锁定和全部调整记录。恢复前验证完整结构、索引、触发器及外键，旧备份先在临时库升级，成功后才回灌；恢复后旧会话失效。

v5账套不能用旧版程序直接打开。回退应使用升级前备份，在独立目录打开。

## 权限

| 操作 | 管理员 | 会计 | 出纳 | 只读 |
|---|:---:|:---:|:---:|:---:|
| 确认锁定期初 | 是 | 否 | 否 | 否 |
| 登记、反向调整 | 是 | 是 | 否 | 否 |
| 查询、导出调整记录 | 是 | 是 | 是 | 是 |

写入在同一数据库事务内校验当前会话和权限，调整与审计日志同时成功或同时回滚。数据库触发器额外拦截改写已锁定期初和修改、删除调整记录。本地文件访问权限仍由操作系统管理。
