# 数据库结构

- 引擎：SQLite 3（`Microsoft.Data.Sqlite` + `SQLitePCLRaw` 自带原生库，自包含发布，无需安装）
- 位置：`%APPDATA%\Cashier\cashier.db`（可用 `--data-dir` 指定其他目录）
- 模式：DELETE（`journal_mode=DELETE`），`foreign_keys=ON`，`busy_timeout=5000`
- 金额：所有金额列均为 `INTEGER`，单位“分”；不使用 REAL 保存金额
- 版本：`PRAGMA user_version`，当前 **4**；升级前自动生成一致性备份

## 1.1.4 新增的版本与会话保护

- `vouchers.revision`、`invoices.revision`：整数修订号，保存时比较表单原修订号；更新触发器也会在审核、反审核、作废等变更时递增，防止旧窗口覆盖新内容。
- `users.auth_revision`：停用、角色变化和密码重置时递增，使已有登录失效。
- `meta['session.epoch']`：账套会话代次，恢复备份时更换；其他进程保存的旧登录同样不能继续写入。
- 恢复先在临时数据库验证全部必要字段、必要索引/触发器和外键，再迁移到当前版本；验证成功后才备份当前库并整体回灌。恢复成功注销会话并关闭应用，需重新启动登录。
- v3→v4 升级在同一事务中添加保护结构；多实例升级会在取得写锁后重新检查版本，避免重复添加字段。升级失败保持原结构，升级前备份保留。

下面的业务表字段说明保留原有字段；新增的修订号和会话字段以上述列表为准。

## 表结构

### users 用户
| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| username | TEXT UNIQUE | 登录名 |
| display_name | TEXT | 姓名 |
| pwd_hash / salt | TEXT | PBKDF2-SHA256（120,000 次迭代，16 字节盐），Base64 |
| role | TEXT | admin / accountant / cashier / viewer |
| is_active | INTEGER | 1 启用 |
| created_at | TEXT | |

### audit_log 操作日志（仅追加）
`id, ts, user_id, username, action, entity, entity_id, doc_no, before_json, after_json, reason`
索引：`ts`、`(entity, entity_id)`。程序不提供删除/修改入口。

### accounts 资金账户
`id, code UNIQUE, name, kind('bank'|'cash'), bank_tail, subject_code, opening_cents, is_active`
余额不落库，由 `期初 + 已审核流水` 实时计算。

### subjects 科目
`id, code UNIQUE, name, direction('in'|'out'), is_active`

### partners 往来单位
`id, code UNIQUE, name, kind('customer'|'supplier'|'both'), contact, phone, address, terms, level,
opening_receivable_cents, opening_payable_cents, is_active`
期初为负表示预收/预付。

### depts / projects / handlers
`depts(id, code UNIQUE, name, is_active)`
`projects(id, code UNIQUE, name, dept_id→depts, owner, is_active)`
`handlers(id, name UNIQUE, is_active)`

### vouchers 单据（核心表）
| 列 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| doc_no | TEXT UNIQUE | SK/ZC/YS/YF/ZZ + yyyyMMdd + 3 位流水 |
| kind | TEXT | income/expense/receivable/payable/transfer |
| nature | TEXT | 业务性质（见业务规则） |
| biz_date / period | TEXT | 业务日期 / yyyyMM |
| amount_cents | INTEGER | `CHECK(amount_cents > 0 AND <= 99999999999)` |
| account_id / to_account_id | INTEGER→accounts | 收付账户 / 转入账户 |
| fee_cents | INTEGER | 转账手续费（另生成支出单） |
| partner_id / project_id / dept_id / subject_id | INTEGER | 外键 |
| handler / summary / note | TEXT | 经办人、摘要（必填）、备注 |
| status | TEXT | `CHECK IN ('draft','pending','audited','void')` |
| count_as_revenue / count_as_cost / invoiceable | INTEGER | 口径标记 |
| created_at/by, updated_at/by, audited_at/by, voided_at/by, void_reason | TEXT | 审计字段 |
| ref_id | INTEGER→vouchers | 关联原单（手续费单指向转账单） |

索引：`biz_date`、`(kind,biz_date)`、`status`、`partner_id`、`project_id`、`account_id`

### settlements 核销分配
`id, pay_voucher_id→vouchers, biz_voucher_id→vouchers, amount_cents, created_at, created_by`
`UNIQUE(pay_voucher_id, biz_voucher_id)` —— 防重复核销；索引两列。

### invoices 发票
| 列 | 说明 |
|---|---|
| kind | out 销项 / in 进项 |
| invoice_type | 发票类型文本 |
| invoice_no / invoice_code | 文本，保留前导零 |
| partner_id | 往来单位 |
| reg_date / deliver_date | 登记日期 / 交票日期 |
| gross_cents / net_cents / tax_cents | `CHECK(gross>0)`、`CHECK(net>0)`、`CHECK(tax>=0)` |
| rate_bp | 税率万分比（600 = 6%）`CHECK 0..10000` |
| status | valid / void |
| created_at/by, voided_at/by, void_reason | |

唯一索引：`ux_invoice_no ON invoices(kind, invoice_no) WHERE status='valid'`

### invoice_links 发票关联业务
`id, invoice_id→invoices, voucher_id→vouchers, amount_cents`
`UNIQUE(invoice_id, voucher_id)`

### periods 期间
`period TEXT PK (yyyyMM), status('open'|'closed'), closed_at, closed_by`

### import_batches 导入批次
`id, ts, file_name, kind, total_rows, ok_rows, fail_rows, user_name, detail_json`（错误行 JSON）

### settings 设置
`k TEXT PK, v TEXT`：`book.name`、`book.currency`、`book.company`、`ui.pageSize`

## 一致性约束（数据库 + 业务层双重保障）

1. 金额上限、正数、状态枚举、类型枚举由 `CHECK` 约束。
2. 外键由 `PRAGMA foreign_keys=ON` 强制。
3. 单据号、发票号、核销组合、往来编码、账户编码由 `UNIQUE` 约束。
4. 状态流转用 `UPDATE ... WHERE status IN (...)` + 受影响行数校验，防重复过账。
5. 多表写入（转账 + 手续费、核销、发票关联、审核 + 日志）均在 `BEGIN IMMEDIATE` 事务内完成，失败回滚。

## 备份与迁移

- 备份：`SqliteConnection.BackupDatabase`（在线备份 API），WAL 下保证一致，不会漏掉未 checkpoint 的数据。
- 恢复：先 `PRAGMA integrity_check` 与版本校验 → 自动备份当前库（`*-before-restore.db`）→ 通过备份 API 回灌 → 再次执行建库/迁移检查。
- 升级：`user_version < CurrentVersion` 时先备份（`*-preupgrade-vX-to-vY.db`）再按版本顺序执行迁移脚本。
