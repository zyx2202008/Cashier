## 五、回归：登录后无法进入主界面（已修复）

**现象**：输入账号密码点击登录后，登录窗口关闭，主界面没有出现，程序直接退出（无任何提示）。

**定位过程**：

1. 检查 `%APPDATA%\Cashier\logs\error.log` —— 为空，说明不是异常崩溃，而是"静默退出"。
2. 直接查询账套数据库：`audit_log` 中存在 `2026-10-29 18:21:23 / 系统管理员 / login` 记录 —— **认证其实成功了**，问题出在登录之后。
3. 新增 `--qa-login-flow` 复现真实路径，输出：

```
已触发登录按钮，DialogResult=True
ShowDialog 返回：True
Application.Windows 数量：0
当前 ShutdownMode：OnLastWindowClose
MainWindow 构造成功
MainWindow.Show 成功，可见=False     ← 关键
```

**根因**：`ShutdownMode` 为默认的 `OnLastWindowClose`。登录窗口是启动阶段的唯一窗口，`ShowDialog()` 返回并关闭它时，窗口数变为 0，WPF 立即启动应用关闭流程；随后的 `MainWindow.Show()` 实际被关闭流程吞掉，窗口不可见，进程退出。

**修复**（`App.ShowLoginAndMain`）：

```csharp
ShutdownMode = ShutdownMode.OnExplicitShutdown;   // 登录期间禁止因窗口数归零而退出
var login = new LoginWindow();
if (login.ShowDialog() != true) { Shutdown(); return false; }

var main = new MainWindow();
MainWindow = main;
ShutdownMode = ShutdownMode.OnMainWindowClose;    // 之后由主窗口关闭决定退出
main.Show();
main.Activate();
if (!main.IsVisible) { /* 记录日志 + 明确提示，不再静默 */ }
```

同时补充了防御：主窗口构造失败时弹出可读错误并写日志，不再静默退出。

**验证**（修复后）：

| 场景 | 结果 |
|---|---|
| `--qa-login-flow`（临时数据目录） | `MainWindow 可见：True`，`RESULT=OK` |
| `--qa-login-flow`（`%APPDATA%\Cashier` 真实账套） | `MainWindow 可见：True`，`RESULT=OK` |
| 退出登录 → 再次登录（同一 `LoginWindow`，主窗口仍在） | 关闭登录窗不会触发退出（`OnMainWindowClose` 且主窗口存在） |
| 关闭主窗口 | 正常退出（`OnMainWindowClose`） |
| 关闭登录窗口（点 X） | `ShowDialog` 返回 null → 显式 `Shutdown()` |
| 财务自检 75 项 | 仍全部通过 |
| ZIP 解压后运行 | 通过 |

**教训**：UI 验证必须覆盖"用户真实操作序列"，不能只验证各页面独立渲染。
