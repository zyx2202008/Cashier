# 业务计算规则

本文件与 [期初锁定与余额调整](期初锁定与余额调整.md) 共同说明1.2.0计算口径。所有金额计算集中在 `Cashier.Core` 业务层，界面层不重复实现公式。

## 1. 金额与精度

| 项目 | 规则 |
|---|---|
| 数据类型 | 业务金额一律 `decimal`，数据库中一律以 **整数分**（`*_cents`，SQLite INTEGER）存储 |
| 换算 | `分 = Round(元 × 100, 0, MidpointRounding.AwayFromZero)`；显示 `分 / 100` |
| 舍入 | 统一 `MidpointRounding.AwayFromZero`（四舍五入），不使用银行家舍入 |
| 小数位 | 入账金额固定 2 位；界面对所有金额使用千分位 + 2 位小数 |
| 范围 | 单笔 `0.01 ~ 999,999,999.99` 元；超出由 `Money.ToCents` 抛错，数据库 `CHECK` 二次兜底 |
| 正负 | 单据金额必须 > 0；负数业务通过“退款 / 冲减 / 供应商退回”等业务性质表达，不允许录入负金额 |
| 汇总 | 汇总一律对“分”求和后再格式化，不在不同报表中重新舍入 |

## 2. 单据类型与业务性质

单据类型（`vouchers.kind`）：`income` 收入、`expense` 支出、`receivable` 应收、`payable` 应付、`transfer` 内部转账。

| 业务性质 | 所属单据 | 资金流入 | 资金流出 | 计入收入发生额 | 计入成本发生额 | 影响客户净应收 | 影响供应商净应付 | 可开票业务 |
|---|---|---|---|---|---|---|---|---|
| 现收收入 SaleCash | 收入 | ✓ | | ✓ | | | | ✓ |
| 客户回款 CustomerReceipt | 收入 | ✓ | | | | −（减少） | | |
| 客户预收 CustomerPrepay | 收入 | ✓ | | | | −（减少，形成预收） | | |
| 供应商退回 SupplierRefund | 收入 | ✓ | | | | | +（增加，冲减预付；正应付场景需业务确认） | |
| 其他收入 OtherIn | 收入 | ✓ | | ✓ | | | | |
| 现付费用 PurchaseCash | 支出 | | ✓ | | ✓ | | | ✓ |
| 供应商付款 SupplierPayment | 支出 | | ✓ | | | | −（减少） | |
| 供应商预付 SupplierPrepay | 支出 | | ✓ | | | | −（减少，形成预付） | |
| 退还客户 CustomerRefund | 支出 | | ✓ | | | +（增加） | | |
| 其他支出 OtherOut | 支出 | | ✓ | | ✓ | | | |

> 关键约束：**收付款单据不重复计入收入/成本**。客户回款只减少应收，不再产生一次收入。

## 3. 状态与过账

状态：`draft` 草稿 → `pending` 待审核 → `audited` 已审核 → `void` 已作废。

- **只有 `audited` 参与余额、报表和发票统计**；草稿与待审核可在界面查看，但报表口径明确排除。
- 审核在单个事务内完成：`UPDATE ... WHERE id=? AND status IN ('draft','pending')`，受影响行数必须为 1，否则报“单据状态已变化”，从数据库层面防止双击/重试重复过账。
- 已审核单据只读，修改必须先反审核。
- **反审核**前置检查：该单据是否存在核销记录、发票关联、关联手续费单据；期间是否已关闭。任一存在则阻止，并提示解除顺序。
- **作废**保留原记录与关联关系，`status='void'`，不参与任何统计；同样需要先解除下游关联。
- 所有状态变更写入 `audit_log`（操作者、时间、动作、原值、新值、原因、单据号）。

## 4. 期间控制

- 期间键 `yyyyMM`，由业务日期推导。
- `periods.status='closed'` 时，该期间禁止：新增、修改、审核、反审核、作废、核销、发票登记/解除关联。
- 重新开启期间需要 `PeriodClose` 权限并强制填写原因，写入日志。
- 关闭期间不改变历史数据，只做写入闸门。

## 5. 资金账户余额

```
账户余额 = 期初余额 + 截止日累计资金流入 − 截止日累计资金流出 + 截止日生效的余额调整
资金流入 = Σ 已审核收入单据金额（account_id = 本账户）
         + Σ 已审核转账单据金额（to_account_id = 本账户）
资金流出 = Σ 已审核支出单据金额（account_id = 本账户）
         + Σ 已审核转账单据金额（account_id = 本账户）
```

- 余额不是可编辑字段，界面不提供直接修改余额的入口。
- 期初准备阶段可维护初始值；管理员确认后锁定。后续通过独立余额调整更正，生效日不得早于登记当天，记录调整前后余额快照和原因。
- 内部转账**不改变全部账户合计**，也不进入收支统计。

## 6. 内部转账

- 转出账户 ≠ 转入账户（业务层校验 + 事务）。
- 一笔转账是一行记录，`account_id` 为转出、`to_account_id` 为转入，**天然在同一事务内**，不存在只落一边的可能。
- 手续费不混入转账金额：`fee_cents > 0` 时在同一事务内**自动生成一张支出单据**（性质 OtherOut，摘要“转账手续费（原单号）”，`ref_id` 指向转账单）。因此手续费计入支出统计，转账金额不计入。
- 重复提交保护：转账单与手续费单在同一事务提交，任一失败整体回滚。

## 7. 往来净额（应收应付）

```
客户净应收 = 期初净应收
           + 截止日生效的客户应收调整
           + Σ 已审核应收单金额
           − Σ 已审核客户回款
           − Σ 已审核客户预收
           + Σ 已审核退还客户

供应商净应付 = 期初净应付
             + 截止日生效的供应商应付调整
             + Σ 已审核应付单金额
             − Σ 已审核供应商付款
             − Σ 已审核供应商预付
             + Σ 已审核供应商退回
```

- 期初值允许为负：客户为负表示**预收**，供应商为负表示**预付**。
- 净额为负时界面显示“预收/预付”而不是归零；不同往来单位的正负余额**不相互抵销**。
- 本期净收款 = 收款 − 退款；本期净付款 = 付款 − 供应商退回（与上式等价）。

## 8. 核销（结算分配）

核销只建立“收付款 ↔ 应收/应付”的分配关系，**不再次改变往来净额**（收付款本身已改变净额）。

- 约束：同一往来单位；应收只能由客户回款/预收核销，应付只能由供应商付款/预付核销；双方均须已审核。
- 单笔核销金额 ≤ 收付款可分配余额，且 ≤ 业务单据未结金额。
- `settlements` 对 `(pay_voucher_id, biz_voucher_id)` 建唯一索引，重复提交被数据库拒绝。
- 自动分配：按业务日期、单据号升序依次分配，剩余金额保留为未分配。
- **核对恒等式**：`Σ单据未结 − Σ收付款未分配 = 往来净余额 − 期初净额`（自检中已验证）。

## 9. 发票

- 发票登记**不改变资金余额**，也不改变往来净额。
- 价税分离（单一税率，整张发票同一税率）：

```
不含税金额 = Round(含税金额 ÷ (1 + 税率), 0, AwayFromZero)   // 以“分”为单位
税额       = 含税金额 − 不含税金额
```

- 校验：`不含税 + 税额 = 含税`（整数分精确相等），税率 0%–100%。
- 校验：按税率对不含税金额重算的税额，与票面税额相差不得超过 1 分（整数分四舍五入容差）。防止手工改数或导入造成“税率与税额不一致”。
- 唯一性：同类型（销项/进项）下**有效发票号码唯一**（部分唯一索引 `WHERE status='valid'`），作废后可重新使用该号码。
- 发票号码、代码按文本保存，保留前导零。
- 关联规则：发票金额 − 已关联金额 = 可关联余额；业务单据金额 − 已开票金额 = 未开票金额；两者都不能被突破；同一发票与同一单据只能有一条关联。
- 未开票金额 = 可开票业务金额 − 已关联有效发票金额，**不等于未收款金额**。

## 10. 项目利润

- 业务发生口径（含税）：`项目利润 = 项目收入发生额 − 项目成本费用发生额`，按单据的 `project_id` 归集。
- 收入发生额 = 现收收入 + 其他收入 + 计入收入的应收单；成本费用发生额 = 现付费用 + 其他支出 + 计入成本的应付单。
- 收付款（回款/付款/预收/预付）**不进入**项目利润，避免与业务单据重复计入。
- 未指定项目的单据归入“(未指定项目)”；公共费用**不做分摊**，报表中明确标注，不等同于企业最终会计利润。
- 项目净收支（另一口径）= 项目实际收款 − 实际付款（资金口径），在账户/收支报表中体现。

## 11. 期初与跨月

- 账户期初、往来单位期初在基础资料中维护，属于账套启用时的时点余额。
- 跨月/跨年余额由“期初 + 期间流水 + 生效余额调整”滚动推导：`本月期初 = 上月期末`，不允许把各月期末相加当作全年余额。余额调整独立列示，不计业务发生额或开票。
- 月/年报表只汇总**发生额**；余额类报表按截止日滚动计算。

## 12. 已知取舍（明确声明）

1. 未实现多币种，全部按人民币记账。
2. 发票仅支持整张单一税率；多税率需拆成多张发票（界面未提供多行明细）。
3. 未实现银行对账、票据管理、固定资产、工资等模块（超出本次范围）。
4. 冲销采用“作废原单 + 重新录入”的方式，未提供一键红冲生成负向单据的专用流程。
5. 1.2.0已提供期初确认锁定及独立余额调整；过往已经被改动的历史需依据备份或原始资料核对。
